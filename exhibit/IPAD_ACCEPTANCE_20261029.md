# 昆虫大学2026：展示用iPadの実機受入手順（2026-10-29）

対象：眼遊タスク **T-003** ／ GitHub Issue [#135](https://github.com/Ganyujapan/Gitai_Lab_Preview/issues/135) ／ 本番展示予定 **2026-11-21**。目標期限は **11-20（仮）**。

## 誰が何をするか

- 開発担当：GitHub上でコード・隔離自動テスト・CI・Pages公開を確認する。
- 展示iPad所有者：下記A/B/Cの**実機試験**だけを行い、結果を**ギタイラボ開発スレッド**に報告する。
- タスク管理：実機結果に基づき「未実施／確認中／合格／要修正」を変更する。**CI成功だけでは実機合格にしない**。

## 本番データを保護する前提（必須）

1. 現在の進化データと既存のJSONバックアップは保存したまま維持。**初期化、サイトデータ削除、PWA削除・再インストール、既存バックアップの廃棄をしない**。
2. Safari／PWAの実際の保存操作が必要な場合は、保存済みファイルをiPad「ファイル」で再確認する。ダウンロード開始と保存成功を同一視しない。
3. 故意に容量不足やライフ保存失敗、アプリ強制終了を発生させない。他タブから実験DBを書き換えない。
4. 実行するURLは `https://ganyujapan.github.io/Gitai_Lab_Preview/exhibit/`。公開サイトと展示用保存領域を混同しない。
5. バックアップv2の**本物の進化データへの分割復元**はIssue [#163](https://github.com/Ganyujapan/Gitai_Lab_Preview/issues/163)の承認が終わるまで**実行しない**。合成隔離試験が合格しても本番復元できるとは限らない。

## 既に実機で合格済み（原則再試験不要）

- 隠れるギタイ：第13世代結果から交代し、第14世代保存。
- 目立つギタイ：第26世代の進化データが保持されていた。
- 結果画面・交代ボタンの表示。
- 合成・隔離バックアップ3試験すべて合格。
- 合成JSONのmanifest＋5パートの計6ファイルをiPadで保存・再選択し、SHA-256と122件の整合性合格。

上記は実データ大容量復元を証明しない。後続試験で意図的な再現・破壊を求めない。

## 優先度A：展示の基本運用（6項目）

- **A-1 最新版**：iPadを接続した状態で展示版モード選択の「アプリ版」（12桁）と「オフライン用ゲームファイルを保存済み」を確認する。表示された文字列をそのまま記録。GitHubの最新コミットと**配信ビルドは別**なので無理に一致と判断しない。更新前にゲームとバックアップ作業が終了していることを確認する。
- **A-2 交代後ライフ10**：目立つギタイの保存済み第26世代（既に先へ進んでいれば現行世代）を普通にプレイし、結果画面の「次の人へ変わる」を押す。次世代（26→27なら27）が保存され、次来場者のライフが10に戻り、蛾の進化データは維持されることを確認する。
- **A-3 同じ人のライフ継続**：交代せず「次の世代を生成」から継続し、ライフが10へ勝手に戻らないことと、子世代と模様が維持されることを確認する。**A-2とA-3は別の分岐**。
- **A-4 5世代制限**：同一来場者が5世代を終えたときの案内・進化シアター・交代を確認。新しい来場者が5世代を使えること。途中でタイトルへ戻る／通常のページ再読み込みで無断リセットされないかも確認（テストのために保存データを消さない）。自動テストはページ再読み込み時のsessionStorageの保持を想定し、Safariのセッション破棄は別途実機確認。
- **A-5 完全オフライン**：まずA-1で資材保存を確認。通信をOFFにした状態で展示ホーム・モード選択・両モードの開始・プレイ・世代更新・交代が正常であること。Safariとホーム画面PWAは実際に展示で使う形態をそれぞれ確認。
- **A-6 再起動後データ保持**：両モードの世代番号と進化画像、必要なライフを記録したうえでゲームを閉じ、再度起動して一致を確認する。端末OS再起動を行う場合も**アプリ削除、ストレージ削除はしない**。

**基本運用合格の判定**：A-1～A-6の全ての実機結果が合格、かつ重大なデータ保護・ライフ・音声障害が確認されないこと。1件でも未確認なら展示の基本運用「実機合格」とはしない。

## 優先度B：安定性（4項目）

- B-1 熱帯雨林BGMを再生し「♪ 音源エラー」の有無、ページ遷移後の状態を確認（PR #169は待機側エラー処理の修正であり、再生自体の実機合格ではない）。
- B-2 捕食・毒のSE、BGMとの同時再生と遅延の体感を確認。
- B-3 進化シアターの世代番号と画像の一致、前後移動、再生、閉じるを確認。
- B-4 展示スタンド・磁気給電での長時間運転、発熱、充電継続、スリープ・復帰を確認。

## 自動テストと実機の違い

- `verify-exhibit-visitor-handover.cjs`：展示用実コードをVMで実行し、世代保存・交代・ライフ10・継続・5世代カウントを検証。OSのSafari終了やiPadでの音／充電は模擬しない。
- `verify-exhibit-offline-navigation.cjs` ／ `verify-exhibit-update-lifecycle.cjs`：SWのキャッシュ、オフラインURL、更新失敗時のロールバックを検証。iPad/PWAのネイティブ挙動は模擬しない。
- テストの追加・修正後も、既に合格した実機試験を無意味に繰り返さない。動作に関わる新規変更がある場合は影響範囲だけ再検証する。
