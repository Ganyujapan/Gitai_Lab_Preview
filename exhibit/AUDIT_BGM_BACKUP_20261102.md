## 2. バックアップ・復元安全性

| 項目 | 現行実装 | 監査結果 |
|---|---|---|
| 本番DB | バージョン2、モード別 | 変更なし |
| 本番バックアップ | v1 JSON・SHA-256検査 | 既存のコード・自動テスト対象 |
| v1書き出し | 3ストア単一のreadonlyスナップショット、現世代60画像・60DNAを検査 | 原子的取得を確認 |
| v1復元 | モード・形式・チェックサム・画像・DNAの検証後、3ストア一括readwrite確定 | 原子的交換を確認 |
| 別タブによる競合 | 世代・restore_epochによる保存直前の変更拒否 | コード・既存テストを確認 |
| 目立つギタイのライフ | localStorageの別保存、partial復元と専用再試行あり | **DBと同時の完全な原子性はない** |
| v1の上限 | **20,000件または150MiB** | 上限超えでは元の保存を保持して拒否 |
| 実ファイルの保存 | 準備後に別のタップで共有・保存、保存済みJSON再選択検証 | iPad実機で確認が必要 |
| 分割v2 | ファイル構造・ハッシュ等の読み取り専用検証と隔離DBでの試作 | **本番書き出し・復元は使用不可** |
| v2一時ストア | DB v3、別名の合成試験DBのみ | 本番DBはv2のまま |

本番データを消去する新たな確定済みバグは、今回の確認範囲では発見していない。ただし**保証ではない**。v1の件数・容量上限、iPad Safariのメモリ／ストレージ枯渇、実ファイル保存成否、ライフの別保存、既存データを使った復元の実機検証は残課題。

### 操作上の重要事項

1. v1書き出しの「準備完了」は保存成功ではない。共有またはダウンロード後、「ファイル」で実在を確認し、保存済みファイルを再選択して読み取り専用検証を行う。
2. 20,000件・150MiBを超えてバックアップが拒否されても、歴史を消したり初期化したりして解決しない。分割v2の本番投入は別途安全審査が必要。
3. 管理者はバックアップ・復元前に他のゲームタブを閉じる。復元のpartialは成功扱いにせず、ライフの再試行手順を守る。
4. 本番のiPad PWAを削除・再インストールしない。OSのサイトデータ削除に備え、検証済みバックアップを別媒体にも保管する。
