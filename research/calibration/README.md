## 分析・評価の取り扱い

1. 人間評価は「完成域／ほぼ完成／非常に優秀／優秀／良好／よく目立つ」の**順序尺度**。0～100点への恣意的な換算は禁止。
2. GITAI SCORE v1の点数と、人間評価は別の指標です。採点時は機械スコアも種親の過去評価も非表示。
3. `sampling.mode=balanced` は旧ランダム評価、`sampling.mode=high` は高評価のGenomeを変異させた候補から上位を選ぶ評価。後者は**無作為抽出ではありません**。
4. データ上の外れ値は原本から削除せず、除外理由を別ファイルで記録して解析時のみ除外してください。
5. 同一背景に複数の背景画像記録があり、背景IDと位置を組み合わせて再現します。

**注意：この研究フォルダは公開GitHubリポジトリに保存されています。** 将来、他の協力者の評価やカスタム背景を保存する場合には公開・著作権・プライバシーの扱いを確認してください。

従来の624件のマニフェストと復元ツールは改変せず、ランダム評価と高擬態評価を別々に保管します。

## 独立1000回最適化・最良1匹の人間評価

- 採点画面の3つ目の選択肢「1000回最適化・最良1匹」。既存ランダム／高擬態評価とは別モードで、従来の2モードは変更なし。
- 毎回新しいランダムGenomeを1つ初期化し、ランダム予備探索80回＋通常の最適化1000回を実行した後、局所v1最良の1匹のみを盲検で提示します。
- 元の最適化と同様に「7.5%ランダム再抽選、残りは現在のベストGenomeに段階的な変異」を実施。ただし通常ラボの best を引き継がず、書き戻さず、毎回独立して初期化します。
- 評価保存後は次の独立最適化を自動で開始。時間がかかる場合は画面上の「探索を中止」で止められます。中止した未完了結果は採点しません。
- 新しいJSONの sampling.mode は optimized1000。optimization_iterations=1000、optimization_warmup_trials=80、optimization_initial_genomes=1、optimization_initialization=fresh_random、candidates_checked=1081 を保存します。
- これは機械スコアで選抜されたデータであり無作為抽出ではありません。v1の高得点が人間の「完成域」を必ず意味するわけではありません。

## 砂地の完成域／ほぼ完成の境界：短時間独立最適化（2026-10-14）

- 人間評価画面の最適化モードは100・200・300・500・1000回から選択可能。従来の1000回モードを保持し、ランダム評価と高擬態評価も維持。
- 各評価を初期ランダムGenomeから独立して最適化し、局所GITAI SCORE v1の最良個体1匹だけを採点前のスコアを隠して表示する。人間評価は探索途中では入力されない。
- 最適化の前にランダム予備探索（warmup）を追加実行する。予備探索回数は min(80, max(20, floor(iterations * 0.08)))。100/200/300/500/1000回に対応する予備探索は20/20/24/40/80回。
- 端末保存と軽量JSONでは sampling.mode が optimized100 / optimized200 / optimized300 / optimized500 / optimized1000、sampling.optimization_iterations が100/200/300/500/1000となる。sampling.candidates_checked には初期候補1＋予備探索回数＋最適化試行回数を記録。
- 砂地は1000回で完成域ばかりだったため、まず200回を検証し、結果に応じて100・300回に変更して「ほぼ完成」も収集する。**試行回数から人間の評価カテゴリを予測・確約してはいけない**。ラベルは必ず人間が判定する。
- 将来の比較では背景・座標・試行回数別に分析し、特に1000回と短時間最適化では人工的な選抜条件が異なることを明示する。
