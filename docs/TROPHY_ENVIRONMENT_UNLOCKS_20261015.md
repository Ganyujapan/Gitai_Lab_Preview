# エンタメ版 — トロフィーによる背景解放仕様（2026-10-15）

## 採用したルール

- 最初は樹皮（bark_001）だけを環境選択画面で選べる。
- SまたはSSの蛾を標本箱に1個体保存すると砂地（sand_001）が解放される。
- SまたはSSを累計10個体保存すると第3環境（背景と名前は未決定）が解放条件達成となる。
- 同じ標本IDの複数保存は1件。背景やRunをまたいだ累計。
- 一度獲得したトロフィーや解放は、標本を後で削除しても取り消さない。
- 樹皮・砂地のゲーム進行は従来の別々のIndexedDBに維持し、切替時にリセットや混合はしない。
- 教育版には進行ロックを適用しない。標本評価が進化の親選抜に影響することもない。

## 実装構成

- js/trophy_rules.js — 認定済みS/SS個体IDの重複排除、累計1/10件による解放の判定。
- js/portal_trophies.js — エンタメ版の環境選択と標本箱（IndexedDB）の確認。
- css/portal_trophies.css — 背景選択UI。
- localStorageに gitai-trophies-v1 を保存し、ブラウザ内で解放を保持。

## 重要：ランク較正が未完了

GITAI SCOREを内部100点満点からD/C/B/A/S/SSに変換する境界は未決定。
仮に「90点以上＝S」などとせず、1,103件の評価に基づく背景別較正・独立検証のあとに導入する。

そのため現状では、新しいUIと永続的な解放台帳だけが動作し、まだ新しいトロフィーは発行されない。ゲームには判定準備中と明示する。

将来、正式な採点器がランクを確定した際、標本レコードに以下を保存する：
- trophy_rank: S または SS
- rank_calibration_version: gitai_rank_calibrated_v1 （正式モデル識別子）

両方を持つエンタメ版標本だけがトロフィーに加算される。既存標本の安全な再評価は別工程。

トロフィーは端末・ブラウザのローカルデータ。別端末とは同期しない。ブラウザデータを全消去すると失われる。
第3環境は条件達成時に「背景準備中」となり、未実装の背景へは遷移しない。
開発用の直接URL (?env=sand_001 等) は当面有効のままで、ロックは公式環境選択UIでの制御である。
